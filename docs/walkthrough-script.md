## 0:30 to 1:30 - The brief

[SCREEN: cut to the JD pinned in a tab; highlight "AI Reel Generator" in the project options list.]

The take-home offered three project options. I chose option three, the AI Reel Generator, for three reasons.

First, I wanted to ship something I would keep using after this interview. I post short-form content, I have a cloned voice ready, and I have a Hetzner deployment pattern I trust. A reel generator is the rare assessment artifact that survives the assessment.

## 1:30 to 3:30 - LangGraph over n8n

[SCREEN: open `docs/decisions/001-langgraph-over-n8n.md` in a markdown viewer.]

The JD lists n8n as the preferred orchestration tool, with "or similar" as the explicit fallback. I picked LangGraph instead. I want to be clear about why, because picking against a preferred-tool signal is a real choice.

n8n is excellent at what it does: visual workflow glue between SaaS apps, low-code triggers, automation a non-engineer can read. If the brief had been "post a Google Sheet row to Slack and back," n8n would be the right tool.

[SCREEN: scroll to the "Why" section of ADR-001 with the bullet list visible.]

This brief is different. The pipeline is a stateful AI graph: typed Pydantic state across nodes, conditional retries on validation failures, a 6-per-minute Replicate rate limit that needs backoff, and a mandatory human-approval gate. n8n can do most of that with bespoke nodes. LangGraph does it natively in Python with a `StateGraph`, typed state, and a single compiled callable that FastAPI wraps.

The other reason: my fail-fast probes are written in Python against the same SDKs the production code uses. With LangGraph there is no second runtime to maintain. The probe that proved Replicate's rate limit and the production code that handles it import the same client.

The story I want to tell is "I picked the right tool for the problem shape," not "I followed the suggestion regardless of fit." That is the same judgment I would make on day one of the role.

## 3:30 to 6:00 - Architecture

[SCREEN: switch to `docs/diagrams.html`, scroll to the Pipeline Flow diagram.]

The pipeline has four nodes plus one mandatory gate. Extract takes the freeform brief and structures it into an `ExtractedIntent`. Plan turns that into a `ScriptPlan` with hook, scenes, voiceover text, and per-scene visual prompts. Approval Gate pauses the entire state machine and waits for me to click Approve. Execute fans out in parallel to TTS, image generation, and captions. Stitch runs ffmpeg to produce the final 1080 by 1920 MP4.

[SCREEN: scroll to the State Object diagram.]

Every node reads from and writes to a single `ReelState` Pydantic model. That state object is the contract between nodes. Cost entries and errors append to side-channel lists so a failure in one node never erases the trace from the others.

[SCREEN: open a `runs/<id>/plan.json` file in the editor, scrolled to show the scenes array.]

The most important artifact in the whole system is `plan.json`. Before any paid Execute call fires, the Plan node writes this file to disk. It contains the hook, the full voiceover script, every scene's visual prompt, the motion type, and the music mood. A human can open it and see exactly what the model decided to generate. If the plan is wrong, you find out for two cents instead of for twenty-five.

[SCREEN: cut to terminal, show the FastAPI route table.]

FastAPI wraps the LangGraph state machine. The API surface is tiny: `POST /api/runs` to start, `GET /api/runs/{id}/stream` for Server-Sent Events, `POST /api/runs/{id}/approve-plan` for the gate, and `GET /api/runs/{id}/reel.mp4` for the result. SSE pipes per-node events to the frontend so the live timeline updates as each node finishes.

## 6:00 to 7:30 - Fail-fast probes

[SCREEN: terminal in `backend/experiments/`, `ls probe_*.py`.]

Before any node code shipped, I wrote ten probe scripts. Each one is a standalone file that calls one external service and exits zero only if the response shape matches what the production code will expect.

[SCREEN: open `probe_03_replicate_flux_schnell_9x16.py` and scroll briefly.]

Probe 03 confirmed Flux Schnell honors aspect ratio nine by sixteen at 768 by 1344, no upscale step. Probe 02 confirmed ElevenLabs returns character-level alignment in the same response as the audio, which means I get captions for free without running Whisper. Probe 09 verified the Langfuse v4 SDK works with my decorator pattern after the v2 examples in the docs turned out to be stale.

[SCREEN: terminal, run `python backend/experiments/probe_10_e2e_minimal.py` live.]

I will run probe 10 live. This is the end-to-end smoke test: a hardcoded plan goes in, an MP4 comes out. No frontend, no LLM, just Execute and Stitch against real ElevenLabs, real Replicate, real ffmpeg.

[SCREEN: probe finishes, prints cost, prints output MP4 path.]

That is the entire fail-fast contract. Every node has a probe; every probe runs against the live runtime; a probe failure blocks the corresponding node from being committed. ADR-009 documents the matrix.

## 10:30 to 11:30 - Observability and cost

[SCREEN: open Langfuse Cloud in a new tab, navigate to the trace for the run that just completed.]

Every LLM call and every external API hit is traced in Langfuse Cloud. You see the four nodes nested under the run, latency per node, token counts, and the dollar cost attached to each span. ADR-006 covers why I chose hosted Langfuse over self-hosting.

[SCREEN: cut to a terminal cat-ing `runs/<id>/cost.json`.]

On disk, every run has a `cost.json` ledger with one entry per paid call. Per-day totals roll up into `cost_cap.json`. Before any paid call, the cost cap helper checks the day's running total. If a new run would push past the daily cap, the request aborts with a clean 402 and zero spend.

The economics: about three cents per 5-second reel, about twenty-five cents for a full 90-second reel. At twenty-five cents a reel, a thousand reels a month is two hundred fifty dollars. I can keep running this on my own dime without thinking about it.

## 11:30 to 13:00 - Failure handling

[SCREEN: open `backend/src/reel_gen/nodes/plan.py` and scroll to the Pydantic validation retry block.]

Five places I handle failure deliberately, not implicitly.

One. The Plan node validates Sonnet's JSON output against the `ScriptPlan` Pydantic model. If validation fails, the node retries up to twice with the validation error fed back into the prompt. On a third failure it falls back to a deterministic template plan. The pipeline always ships a reel.

[SCREEN: cut to `backend/src/reel_gen/media/replicate_flux.py`.]

Two. Replicate Flux occasionally rejects a prompt as NSFW. Probe 04 documented the exact error string. The image client catches it once, deterministically rewrites the prompt to a safer variant, and retries.

Three. ElevenLabs Music can fail. If it does, the music path becomes None and Stitch handles silence cleanly. ADR-008 covers why I skip music at the 5-second default anyway.

[SCREEN: cut to `backend/src/reel_gen/nodes/execute.py`.]

Four. If a single scene image fails after retries, the reel falls back to a solid-color frame with the scene's voiceover excerpt overlaid. One bad image does not kill the whole run.

Five. The cost cap aborts BEFORE the call, not after. ADR-012. A leaked password cannot blow the budget because the wall is dollar-amount, not user-identity.

## 13:00 to 14:00 - Production deployment

[SCREEN: terminal, ssh into the Hetzner box, `docker compose ps` showing both services healthy.]

The whole stack runs on a single Hetzner Cloud VM. Docker Compose brings up two services: the FastAPI backend and the Next.js frontend. nginx is the reverse proxy, terminating TLS via Let's Encrypt for `studio.sshub.dev`, with SSE keep-alive timeouts tuned so long-running runs do not get cut off.

[SCREEN: cut to the diagrams.html Deploy Stack diagram.]

Auth is HTTP basic at the nginx layer. Two credential pairs in `.htpasswd`: one for me, long-lived; one for CSC, scoped to the interview window and revoked after. Cheapest possible gate. ADR-012.

Secrets live in `.env` on the server only, never in git. The runs directory is a named volume so generated reels survive container restarts. The deploy script bumps `APP_VERSION` before each push so I can tell which build is running by hitting `/healthz`.

---

## 14:00 to 14:30 - What's next and limits

The honest limits. The deploy is single-user-plus-assessor by design; no real auth, no per-user attribution, no rate limiting beyond the cost cap. Inline scene editing in the approval panel is not shipped; you get Approve or Reject only. Music gen at 30 seconds and up is wired but not extensively tested. There is no Instagram posting integration; you download the MP4 and post it yourself.

Stretch goals if I keep building: inline plan editing, multi-brand presets, per-scene regeneration. None of those block the assessment.
